# Правила проекта

- При каждом коммите **обязательно** повышать версию проекта в файле `src/Directory.Build.props`. Это обеспечивает корректную работу автопубликаций и позволяет CI‑pipeline правильно определять новые релизы.
- Версия должна быть увеличена **по патч‑номеру** (меньший шаг, чем мажор/минор). Пример: `0.2.16 → 0.2.17`.
- При изменении версии обновлять также файл `README.md`, если в нём указана текущая версия.
- При несоответствии версии и коммита CI‑pipeline будет падать с ошибкой `VersionMismatch`. 
- Любое изменение файлов должно быть зафиксировано локальным коммитом перед любыми другими действиями (push, merge и т.д.).
- Перед ответом пользователю выполнять `git status` и `git diff`; если есть незакоммиченные изменения или отклонения, исправлять их и повторять проверку до полного соответствия.
- Перед выполнением `git push` проверять, была ли повышена версия в `src/Directory.Build.props`; если нет – автоматически увеличить патч‑номер и закоммитить, затем выполнить `git push`.
- Перед `git push` удостовериться, что нет незакоммиченных файлов; если есть – добавить их, создать коммит с сообщением "auto: commit pending changes" и только после этого выполнять push.
- Любое изменение файлов в репозитории должно быть зафиксировано локальным коммитом перед любыми действиями (push, merge и т.д.).
