# MemPulse

**MemPulse** — приложение для контроля использования оперативной памяти в Windows 10/11 и Linux (x64, ARM64). Интерфейс на русском языке. На Windows используется WPF, на Linux — отдельный графический интерфейс Avalonia.

[**Скачать последнюю версию**](https://github.com/rkfsociety/MemPulse/releases/latest)

## Возможности

- Загрузка ОЗУ в процентах, график и показатели памяти.
- Приложения сгруппированы по имени: в разделе «Процессы» можно раскрыть группу, увидеть отдельные PID и при необходимости очистить память одного процесса.
- Все разделы — «Обзор», «Процессы», «Настройки» и «О программе» — открываются в одном окне.
- Очистка кэша ожидания и дополнительные операции с памятью.
- Автоматическая очистка по заданному порогу (по умолчанию выключена).
- Процент занятой памяти в системном трее.
- Проверка и установка обновлений.

### Управление интерфейсом

- **Ctrl+F** — перейти к поиску процессов (Windows) или установить фокус на поиске (Linux).
- **Esc** в строке поиска — очистить запрос; **F5** — обновить показатели.
- В Linux карточки памяти перестраиваются в две строки при сужении окна, а длинный список процессов можно раскрывать порциями кнопкой «Показать ещё».

## Windows: установка и использование

1. Скачайте **`MemPulse-Setup-x64.exe`** из последнего релиза и запустите установщик.
2. Откройте MemPulse для просмотра памяти и процессов. Для мониторинга права администратора не нужны.
3. Для очистки памяти используйте **«Запустить от администратора»**, выберите нужные операции и нажмите **«Очистить выбранное»**.
4. Перейдите в раздел **«Настройки»** слева для управления автоочисткой, автозапуском и треем. Изменения сохраняются кнопкой **«Сохранить»**.

Для проверки новой версии нажмите **«Обновления»**. Портативный `MemPulse.exe` тоже доступен, но встроенное обновление через установщик переводит его на установленную версию.

> **Важно:** очистка памяти не увеличивает объём ОЗУ и не гарантирует ускорения Windows. Принудительная очистка может временно замедлять программы. Для обычного использования достаточно мониторинга.

## Linux: установка и использование

Поддерживаются настольные дистрибутивы Linux с графической сессией X11/Wayland (при необходимости через XWayland). Сборки содержат .NET 8; отдельно устанавливать .NET не нужно. Linux-версия использует Avalonia и не зависит от WPF.

1. Скачайте **`MemPulse-linux-x64.tar.gz`** для обычного ПК или **`MemPulse-linux-arm64.tar.gz`** для ARM64 из [последнего релиза](https://github.com/rkfsociety/MemPulse/releases/latest).
2. Распакуйте архив и запустите программу:
   ```bash
   mkdir -p MemPulse
   tar -xzf MemPulse-linux-x64.tar.gz -C MemPulse
   cd MemPulse
   chmod +x MemPulse.Linux
   ./MemPulse.Linux
   ```
3. Для установки в меню приложений без прав root из распакованного каталога выполните `bash install.sh`. Приложение установится в `${XDG_DATA_HOME:-$HOME/.local/share}/MemPulse`.

Linux-версия отображает физическую память, доступный объём, файловый кэш и процессы (RSS и VmData), объединяя процессы по имени. Данные берутся из `/proc/meminfo` и `/proc/<PID>/status`; мониторинг работает без root.

### Автоочистка на Linux

1. Включите **«Автоочистка»** в главном окне. Укажите порог занятой памяти (70–98 %, по умолчанию 90 %) и паузу между попытками (5–120 минут, по умолчанию 15).
2. Нажмите **«Применить автоочистку»** и одобрите запрос `pkexec` через polkit. Автоочистка по умолчанию отключена.
3. После одобрения отдельный привилегированный помощник проверяет память каждые 5 секунд и при превышении порога выполняет `sync` и `/proc/sys/vm/drop_caches=3`. Пауза действует **и после неуспешной попытки**.
4. Для остановки снимите флажок и нажмите **«Применить автоочистку»**. Помощник также прекращает работу при закрытии MemPulse. Включённое состояние сохраняется, но **при следующем запуске потребуется повторная авторизация polkit**. Если `pkexec` отсутствует или доступ запрещён, функция не включится.

### Очистка памяти выбранного процесса на Linux

Раскройте группу приложений в разделе **«Процессы»** и нажмите **«Очистить PID»** рядом с нужным процессом. MemPulse заново проверяет идентификатор процесса, запрашивает права через `pkexec`, затем использует системные вызовы `pidfd_open` и `process_madvise(MADV_PAGEOUT)` (Linux 5.10+). Операция ограничена **128 МиБ** за запрос и затрагивает только подходящие приватные анонимные отображения памяти. Это **не** завершение процесса и **не** гарантированное снижение RSS: часть страниц может не быть освобождена, а выгрузка активных страниц может замедлить приложение.

Для работы требуются права на просмотр памяти целевого процесса и способность `CAP_SYS_NICE` у привилегированного помощника. В ограниченных контейнерах, средах с политиками безопасности и старых ядрах запрос может быть отклонён; MemPulse сообщает об ошибке без ложного уведомления об успешной очистке.

> **Важно для Linux:** сброс файлового кэша `drop_caches=3` освобождает только подходящие страницы файлового кэша и структуры ядра. Он не увеличивает объём ОЗУ, не гарантирует ускорение и может ухудшить производительность. Включайте автоочистку только при обоснованной необходимости.

### Сборка Linux из исходников

```bash
dotnet build src/MemPulse.Linux/MemPulse.Linux.csproj -c Release
dotnet run --project tests/MemPulse.LinuxTests/MemPulse.LinuxTests.csproj -c Release
dotnet run --project src/MemPulse.Linux/MemPulse.Linux.csproj -c Release
```

## Автоматические релизы

При повышении версии в `src/MemPulse/MemPulse.csproj` на ветке `main` GitHub Actions собирает Windows и Linux, выполняет проверки и публикует Release. Версии обоих проектов должны совпадать. Если публикация отклонена с `HTTP 403: Resource not accessible by integration`, можно добавить секрет репозитория `MEMPULSE_RELEASE_TOKEN` — fine-grained GitHub token с правом **Contents: Read and write** для этого репозитория. В отсутствие секрета используется стандартный `GITHUB_TOKEN`. После настройки можно повторить workflow через **Run workflow** без нового коммита; артефакты сборки сохраняются в запуске Actions на 14 дней даже при ошибке публикации.

## Если возникла ошибка

В Windows откройте в Проводнике `%LOCALAPPDATA%\MemPulse\Logs` и приложите свежий файл `.log` к [сообщению о проблеме](https://github.com/rkfsociety/MemPulse/issues). Перед отправкой проверьте журнал на наличие личных путей и других данных.
